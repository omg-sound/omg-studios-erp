# 외부 일정 캘린더 제목에 장소 붙이기 — 설계

- 요청일: 2026-08-03 (사용자)
- 상태: **구현 완료**(2026-08-03) — 배포 전
- 관련 코드: `src/routes/sessions.routes.js`(`eventInputForSession`·`/sessions/place-suggest`) · `src/data/sessions.js`(`sessionFields`) · `src/views.sessions.js`(장소 주소 칸) · `public/js/app.js`(`[data-place-suggest]`) · `src/db.js`(마이그레이션)

## 1. 무엇을 바꾸나

외부 장소 세션의 구글 캘린더 **제목 맨 뒤에 짧은 위치 라벨**을 붙인다.

```
루나 · 뮤직팜 @잠실실내체육관
루나 · 뮤직팜 @이태원로15길 27-3
루나 · 뮤직팜 @튀르키예 이스탄불
(취소) 루나 · 뮤직팜 @장충체육관
```

지금도 주소는 캘린더 **위치(location) 필드**에 들어간다. 그런데 월간뷰·알림·목록에는 제목만 보여서, 어디서 하는 일정인지 열어봐야 안다. 그래서 위치 필드는 그대로 두고(길찾기용 전체 주소) 제목에 요약을 더한다.

### 사용자가 확정한 것 (2026-08-03)

| 결정 | 값 |
|---|---|
| 라벨 출처 | 자동완성에서 **고른 값을 함께 저장** |
| 해외 표기 | **국가 먼저** — `튀르키예 이스탄불` |
| 제목 형식 | `@` 구분 — `제목 @라벨` |
| 적용 범위 | **외부 일정만**(스튜디오 룸 세션은 제목 무변경) |

### 라벨 규칙 (실측으로 확정 — §5 참조)

**국내(`country.shortText === "KR"`)인지 먼저 가르고**, 국내 안에서 장소/주소를 가른다.

| 경우 | 판정 | 라벨 | 실측 예 |
|---|---|---|---|
| 국내 장소 | `types`에 `establishment` | `displayName` | `잠실실내체육관` · `장충체육관` |
| 국내 주소 | 그 외(`street_address` 등) | `동네 + 번지` 조립 | `이태원로15길 27-3` · `이태원동 181-53` |
| 해외 | `country ≠ KR` | `국가 도시` | `튀르키예 이스탄불` · `미국 뉴욕` |
| 해외(도시 불명) | 〃 | `국가` | `튀르키예` |

국내는 **가장 구체적인 것**(거기까지 찾아가야 하니까), 해외는 **광역**(어느 나라 일인지가 정보다)이라 규칙이 갈린다 — 의도된 비대칭.

**국내 주소 조립** = `sublocality_level_4`(도로명: 이태원로15길) 또는 `sublocality_level_2`(법정동: 이태원동) + `premise`(번지: 27-3). ⚠️ `mainText`를 그냥 쓰면 **구가 따라붙는다**(`용산구 이태원로15길 27-3`) — 사용자 결정은 **구 제외**. 조립에 실패하면(둘 중 아무것도 없으면) `shortFormattedAddress`로 폴백한다(구가 붙더라도 라벨이 없는 것보다 낫다).

**국내 장소는 `mainText`가 아니라 `displayName`을 쓴다** — 주소 유형에서 `displayName`이 `27-3`처럼 번지 조각만 오기 때문에 유형을 갈라야 하고, 장소 유형에서는 둘이 같은 값이다.

국가·도시명은 구글 한국어 표기를 그대로 쓴다. **관용 표기로 바꾸지 않는다**(터키→튀르키예로 나온다). 별칭 표를 두면 그 표를 영원히 관리해야 하고, 구글 표기가 여권·항공권 표기와 같은 쪽이다.

⚠️ **일부 도시는 구글이 한국어 표기를 주지 않는다** — 멕시코시티는 `locality`가 `Ciudad de México`(원어)로 와서 라벨이 `멕시코 Ciudad de México`가 된다(같은 응답에서 장소명은 `멕시코시티 아레나`로 한국어인데 도시 필드만 원어다). **그대로 두기로 했다**(사용자 결정 2026-08-03) — 별칭 표를 만들면 그 표가 계속 자라고, 읽는 데 지장은 없다.

## 2. 지금 구조 (바꾸기 전)

```
세션 폼 ─ 장소 select(room_id) ─ is_external 이면 주소칸 노출
                                  └ <input name="location">  ← 자동완성(Places)
                                        │
sessionFields()  location = 외부 룸일 때만 저장 (아니면 null)
                                        │
eventInputForSession()  title = "아티스트 · 제작사"      ← 여기엔 장소가 없다
                        location = session.location || 스튜디오 기본 장소
```

**핵심 제약**: `/sessions/place-suggest`가 Places autocomplete 응답에서 `text`(전체 문자열) 하나만 남기고 **`placeId`와 구조화 필드(장소명·지역)를 버린다**(`sessions.routes.js:244-248`). 그래서 저장된 `location`은 "대한민국 서울특별시 용산구 이태원로15길 27-3" 같은 한 덩어리 문자열이고, 여기서 국가·도시를 다시 뽑으려면 문자열 추측을 해야 한다.

## 3. 설계

### 3.1 라벨은 "고를 때" 만든다 (저장 경로에 외부 API를 넣지 않는다)

```
① 타이핑    → /sessions/place-suggest        (지금과 동일 + placeId 반환)
② 항목 선택 → /sessions/place-label?id=<placeId>   ← 신설
                 서버가 Places Details 1회 호출 → addressComponents로 라벨 계산
              ← { label: "튀르키예 이스탄불" }
              app.js가 hidden [name=location_label]에 채움
③ 저장      → 서버는 그 문자열을 그대로 저장 (외부 호출 없음)
```

**왜 저장 시점이 아니라 선택 시점인가**: 라벨을 저장할 때 계산하면 세션 저장이 외부 API 응답에 묶인다. 구글이 느린 날 예약 저장이 같이 느려지는 건 받아들일 수 없다(캘린더 동기화를 fail-safe로 둔 것과 같은 이유). 고르는 순간은 이미 사용자가 네트워크를 기다리는 중이라 한 번 더 붙어도 체감이 없다.

**왜 autocomplete 텍스트 파싱이 아니라 Details인가**: 규칙이 "국내면 장소명, 해외면 국가+도시"라 **국가 판정에 전부 걸려 있다**. 응답 문자열에서 국가를 찾으려면 콤마로 쪼개 마지막 조각을 보는 식의 추측이 필요한데, 한국어 로케일에서 국내 주소는 "대한민국"이 앞에 오고 해외는 뒤에 오는 등 유형마다 형태가 갈린다. `addressComponents`는 `country`·`locality`가 타입으로 붙어 오므로 추측이 필요 없다. 국내 판정도 `country.shortText === "KR"` 하나로 끝난다.

**신뢰 경계**: 라벨은 클라이언트가 보낸 문자열이다. 내부 도구(로그인한 직원만)이고 이 값이 하는 일은 캘린더 제목 표기뿐이라 수용한다. 길이 상한(40자)과 개행 제거만 서버에서 건다.

### 3.2 저장 — 컬럼 하나

```js
addColumn("sessions", "location_label", "TEXT"); // 캘린더 제목에 붙일 짧은 장소 라벨. NULL이면 제목 무변경.
```

국가·도시를 따로 두지 않는 이유: 지금 쓰임이 "제목에 붙일 한 줄" 하나뿐이라, 나누면 조합 규칙이 저장부와 표시부 두 곳에 생긴다. 규칙이 바뀌면 어차피 Places를 다시 조회해야 하므로 컬럼을 쪼개도 재계산이 공짜가 되지 않는다.

`sessionFields`는 `location`과 **같은 조건**으로 다룬다 — 외부 룸이 아니면 `null`. (장소를 스튜디오 룸으로 되돌렸는데 라벨만 남아 제목에 옛 장소가 붙는 일이 없어야 한다.)

### 3.3 🔒 라벨과 주소는 함께 움직인다

**주소칸을 손으로 고치면 라벨을 비운다**(app.js). 이게 없으면 "장충체육관"을 골랐다가 주소를 딴 곳으로 바꿔 저장했을 때 **제목에는 장충체육관이 그대로 남는다** — 화면에 보이는 주소와 캘린더 제목이 서로 다른 곳을 가리키는 상태가 되고, 사용자는 제목만 보고 움직인다.

- 자동완성에서 고름 → 라벨 채움
- 주소칸에 타이핑(`input` 이벤트) → 라벨 비움
- 다시 고름 → 다시 채움

### 3.4 자동완성 없이 직접 친 주소

라벨이 없으므로 **제목에 아무것도 붙이지 않는다**(기존과 동일한 제목).

입력값을 그대로 붙이는 안도 있었지만 택하지 않는다 — 손으로 치는 값은 "서울시 용산구 이태원로 15길 27-3 3층 스튜디오" 같은 긴 문장이 되기 쉽고, 그걸 제목에 붙이면 월간뷰에서 아티스트 이름이 밀려난다. 요청의 목적이 "짧은 위치"였다.

라벨을 손으로 고치는 칸도 두지 않는다(2026-08-03 사용자 결정) — 칸이 하나 늘고, 자동으로 채운 값과 손으로 고친 값이 섞이면 "왜 이렇게 나왔지"를 따라가기 어려워진다. 멕시코시티 같은 예외는 그대로 두기로 한 것과 같은 판단이다.

> 📌 남겨두는 여지: 실사용에서 "제안에 안 뜨는 장소"가 잦으면, 짧게 친 값(20자 이하)만 그대로 붙이는 절충안을 그때 더한다.

### 3.5 제목 조합

`eventInputForSession`:

```
[(취소) ] + (아티스트 · 제작사 | 프로젝트명 | "스튜디오 세션") + [ @라벨]
```

- 취소 접두는 **맨 앞** 유지(지금과 동일).
- 라벨은 **맨 뒤**.
- 라벨이 있을 때만 ` @`를 붙인다. 외부 룸이 아니면 애초에 라벨이 `null`이라 자연히 제외된다.

### 3.6 이미 등록된 일정

기존 세션은 `location_label`이 `NULL`이라 제목이 그대로다. 그 세션을 **다시 저장하면** 주소를 자동완성에서 다시 골라야 라벨이 생긴다(옛 `location` 문자열만으로는 만들 수 없다 — 그래서 파싱안을 안 쓴 대가다).

환경설정의 **[기존 캘린더 일정 재동기화]** 는 라벨이 있는 세션만 제목이 바뀐다. 소급 적용은 하지 않는다(외부 일정이 많지 않고, 과거 일정 제목을 일괄로 흔드는 편익이 작다).

## 5. 실측 결과 (2026-08-03 — 사용자가 운영 키로 표본 7건 조회)

| 질의 | `types` | `displayName` | `mainText` | 확정 라벨 |
|---|---|---|---|---|
| 잠실실내체육관 | `gym,…,establishment` | 잠실실내체육관 | 잠실실내체육관 | `잠실실내체육관` |
| 장충체육관 | `arena,event_venue,…,establishment` | 장충체육관 | 장충체육관 | `장충체육관` |
| 이태원로15길 27-3 | `street_address` | **27-3** | **용산구** 이태원로15길 27-3 | `이태원로15길 27-3` |
| 이태원동 181-53 | `street_address` | **181-53** | **용산구** 이태원동 181-53 | `이태원동 181-53` |
| 이스탄불 | `locality,political` | 이스탄불 | 이스탄불 | `튀르키예 이스탄불` |
| Arena Ciudad de México | `event_venue,…,establishment` | 멕시코시티 아레나 | Arena Ciudad de México | `멕시코 Ciudad de México` |
| Madison Square Garden | `arena,…,establishment` | 매디슨 스퀘어 가든 | Madison Square Garden | `미국 뉴욕` |

이 표가 규칙을 바꾼 근거다:

- **`displayName`은 주소 유형에서 쓸 수 없다**(`27-3`·`181-53`) → 장소/주소를 `types`로 갈라야 한다.
- **`mainText`는 국내 주소에서 구를 달고 온다** → 사용자 결정(구 제외)을 지키려면 `addressComponents` 조립이 필요하다.
- **도시는 `locality`로 잘 온다**(뉴욕도 `locality=뉴욕`) — `administrative_area_level_1` 폴백은 그대로 두되 실제로는 거의 안 쓰일 것이다.
- **`languageCode=ko`가 모든 필드를 번역해 주지는 않는다**(멕시코시티) — 위 ⚠️ 참조.
- 띄어쓰기는 구글 표기를 그대로 쓴다(`이태원로15길`, 붙여쓰기).

조사 스크립트: `scratchpad/probe-places.js`(일회성, 저장소에 커밋 안 함). 키는 가려 받아 메모리에만 두고 결과 파일에 남기지 않았다.
