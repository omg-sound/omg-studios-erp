# 환경설정 인라인 편집 + 통합 저장(단가표·룸·작업 종류) 설계

- 날짜: 2026-07-27
- 상태: 설계 확정(사용자 승인) → 구현 계획으로
- 요청: "접지 말고 그냥 바로 기록하고 저장 버튼은 통합 저장 버튼으로 — 하나하나 들어가서 수정하는 게 너무 번거로움" + "한 줄에 내용 다 넣어줘"

## 배경

환경설정의 관리 목록 3곳(단가표·룸·작업 종류)이 같은 패턴을 쓴다: 행 = 요약 + 접이식 `<details>` '수정' 폼 + 행별 저장 버튼. 두 가지 불만이 확인됐다.

1. 저장(POST → `/settings?tab=…` 리다이렉트)하면 접이식·스크롤이 전부 초기화돼 "페이지가 다른 상태로 바뀐다".
2. 항목마다 펼치고 → 고치고 → 저장을 반복해야 해서 번거롭다.

처음 제안(리다이렉트에 `?edit_rate=N#앵커`를 실어 상태 복원)은 사용자가 **인라인 편집 + 통합 저장 재설계로 대체**했다(그 제안은 폐기). 인라인이면 접힐 상태 자체가 없어 1번 문제도 함께 사라진다.

**사용자 결정(2026-07-27)**: ①적용 범위 = 단가표 + 룸 + 작업 종류 세 섹션 전부. ②단가표의 분류별 접이식도 제거 — 분류 헤더 줄만 남기고 전부 펼침, **항목 한 줄에 모든 필드**.

## 행 레이아웃 — 한 줄 편집 필드

'수정' `<details>`·파생 요약 줄(`기준 4시간 · ₩400,000 · 초과…`)·가격유형 배지를 제거하고, **필드 자체가 행 내용**이 된다. 데스크톱(sm+)은 한 줄 그리드, 섹션 상단에 열 제목 1줄(sm+에서만 표시). 모바일(<640px)은 행이 2줄로 감기고 열 제목 대신 필드별 `aria-label`(+짧은 placeholder) — 함정 #28 규칙(flex-wrap·break-keep·컨트롤 묶음) 적용.

| 섹션 | 한 줄 구성 (왼→오) |
|---|---|
| 단가표 | 이름 · 분류▾ · 기준(h) · 기준가(원) · 초과단위(h) · 초과단가(원) · 가격유형▾ · ↑ ↓ · 비활성/삭제 |
| 룸 | 이름 · 상위 룸▾ · ☑예약 대상 · ☑외부 장소 · ↑ ↓ · 삭제 |
| 작업 종류 | 이름 · 과금▾ · 기본 단가(원) · 가격유형▾ · ☑빠른추가 · ↑ ↓ · 삭제 |

- 단가표 분류: `<details>` 접이식 제거 → 분류명 헤더 줄(개수 포함)만 남기고 그 아래 행 나열. 분류 순서·행 순서는 기존 그대로(kind→sort_order).
- 비활성 단가 항목: 지금처럼 행 `opacity-60` + '다시 활성으로' 버튼. `(비활성)` 텍스트 표기는 유지.
- 룸 계층: 하위 룸 들여쓰기(`ml-4`)·`└` 표기 유지.
- 환경설정 페이지의 읽기 폭(`max-w-content` 768px) 안에서 한 줄이 성립하도록 입력은 `text-sm` 컴팩트, 이름 열만 넓게. 폭·감김은 오프스크린 iframe 실측으로 검증(390px 가로 오버플로우 0).

## 통합 저장

- 섹션당 **큰 `<form>` 하나**(전 행의 입력 포함) + 맨 아래 **[통합 저장]** 버튼 1개 + 기존 dirty 패턴(`data-dirty-form`/`data-dirty-save`/`data-dirty-hint`) 재사용 — 아무 칸이나 바뀌면 버튼 강조.
- 필드명 = `<기존 필드명>_<행 id>`: `rate_name_7`·`category_7`·`base_hours_7`·`base_price_7`·`extra_hours_7`·`extra_price_7`·`price_type_7` / `room_name_2`·`parent_id_2`·`bookable_2`·`is_external_2` / `label_3`·`billing_type_3`·`unit_price_3`·`price_type_3`·`is_quick_3`.
- 새 라우트 3개(`requireStaff`): `POST /settings/rate-items/bulk` · `POST /settings/rooms/bulk` · `POST /settings/task-types/bulk`.
- **서버 파싱은 DB 기준**: 현재 행 목록을 조회해 각 id에 대해 `이름 필드(rate_name_<id> 등)`가 body에 존재하면 그 행의 필드들을 모아 **기존 행 단위 함수**(`updateRateItem`/`updateRoom`/`updateTaskType`)를 호출 — 검증 규칙 재사용, 임의 id 주입은 자연 무시. 전체를 **한 트랜잭션**(BEGIN IMMEDIATE)으로.
- 행 단위 오류(이름 비움 = `RATE_NAME_REQUIRED`/`ROOM_NAME_REQUIRED`/`TASK_TYPE_LABEL_REQUIRED`, 단가표 가격 누락 = `RATE_PRICE_REQUIRED`)는 **그 행만 조용히 건너뛴다** — 현행 단건 저장과 같은 의미론(트랜잭션은 커밋, 해당 행만 미적용). 그 외 오류는 롤백 후 전역 핸들러로.
- **체크박스**: 행 참여가 확인되면(이름 필드 존재) 미전송 체크박스 = 해제(0) — 현행 단건 폼과 동일.
- 저장 후 리다이렉트에 **섹션 앵커**를 붙여 스크롤 복귀: `/settings?tab=content&flash=saved#rates-section`(단가표)·`#task-types-section` / `/settings?tab=settings&flash=saved#rooms-section`(룸). 섹션 컨테이너에 해당 `id` 부여.

## 행별 즉시 액션 (유지)

↑↓ 이동·삭제·비활성 토글(단가표)은 지금처럼 **행에서 즉시 실행**. 단:

- **중첩 폼 금지**(장비 대장에서 실증된 브라우저 동작): 액션 폼 태그는 섹션 큰 폼 **밖**(형제)에 hidden으로 두고, 행 안 버튼은 `form="<폼 id>"` 속성으로 연결. `data-confirm`(삭제 확인 문구)은 기존 그대로 유지.
- 액션 리다이렉트에도 해당 **섹션 앵커** 부착(현행 `?tab=…`만 → `?tab=…#<섹션>` — 이동·삭제 후에도 그 자리 근처 복귀).
- **알려진 트레이드오프(사용자 수용, 2026-07-27)**: 필드를 고쳐 놓고 저장 전에 ↑↓·삭제·비활성을 누르면 페이지 리로드로 **미저장 변경이 유실**된다. 1차는 "저장 먼저" 관례로 수용, 실사용에서 걸리면 경고 후속.

## 기존 코드와의 정합

- **app.js MONEY 정규식 확장**: 금액칸 이름이 `base_price_<id>`·`extra_price_<id>`·`unit_price_<id>`로 바뀌므로 콤마 포맷 정규식에 `base_price_\d+|extra_price_\d+|unit_price_\d+` 추가(기존 `task_amount_\d+` 방식과 동일). 가드 ⑫(금액칸↔MONEY 계약)가 기계 검사.
- 가드 ①(bare name 금지): `rate_name_<id>`·`room_name_<id>` 등 접미사 붙은 이름이라 해당 없음.
- 기존 단건 라우트(`POST /settings/rate-items/:id` 등)는 **호출 폼이 사라지지만 라우트는 유지**(외부 계약 아님·제거 무이득, 죽은 라우트 정리는 별도 판단).
- 신규 항목 추가 폼·분류 관리·기본 세션 시간 등 다른 섹션은 무변경.

## 테스트

- **bulk 라우트 데이터 테스트**(신규): 3섹션 각각 — 여러 행 동시 갱신 / 이름 비운 행만 건너뛰고 나머지 적용 / 임의 id 주입 무시 / 체크박스 미전송=해제 / 트랜잭션(중간 예외 시 롤백).
- **뷰 계약 테스트**: 접이식(`<details>`) 제거·행 버튼 `form=` 연결(중첩 폼 없음)·필드명 `<field>_<id>` 규칙·섹션 앵커 id 존재.
- 가드 ⑫(MONEY)·⑩(CSP)·guardrails-ui는 기존 기계 검사로 커버.
- 반응형(390px 가로 오버플로우 0)은 오프스크린 iframe 실측(jsdom 불가 — 함정 #28).

## 범위 밖

- 다른 접이식 편집(분류 관리·담당자·외주 등) — 이번 3섹션 실사용 후 같은 패턴으로 확장 검토.
- dirty 상태에서 행 액션 클릭 시 경고(트레이드오프 항목) — 후속.
- 단건 저장 라우트 제거.
