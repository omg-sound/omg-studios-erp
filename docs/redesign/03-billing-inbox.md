# 개편 3단계 — 청구 대기함 · 직접 기입 청구서 · 단가표 제거 (설계)

> 2026-10-13 작성. 전체 방향·확정 결정은 메모리 `erp-redesign-2026-10`.
> 개편 단계: 1 빠른 생성(배포) → 2 곡 계층 제거(배포) → **3 청구 대기함** → 4 정리.

## 1. 목표

```
지금:  프로젝트 → 청구 탭 → (그 프로젝트 항목만) 체크 → 단가표 자동 산정 → 청구서
3단계: 청구 대기함(모든 프로젝트의 미청구 세션·작업) → 골라서 → 금액·내용 직접 기입 → 청구서
```

이미 확정된 결정(2026-10-13): 여러 프로젝트 혼합 허용 · 부분 청구 없음(계약금 등은 자유 라인) · 단가표 완전 제거 · 발행 청구서 수정 불가(삭제 후 재발행) · 외주 정산·스탭별 매출 유지(자유 라인은 미귀속).

## 3. 화면

### 3-1. 청구 대기함 (`/invoices/inbox`, 사이드바 '청구' 첫 화면)
```
청구 대기 14건                                     [청구서 만들기 (3)]
[검색: 프로젝트·아티스트·제작사]  [기간 ▾]  [완료만 ☐]  [청구 안 함 보기 ☐]

▾ 도너츠컬처 진혁                         제작 도너츠컬처
   ☑ 10/02 · 녹음 · 3시간            완료      ₩300,000(확정액)
   ☐ 10/09 · 녹음 · 4시간            예정
▾ 도너츠컬처 정효빈                       제작 도너츠컬처
   ☑ 내 안의 그대 - 믹싱              완료
   ☑ 내 안의 그대 - 마스터링          완료
```
- **모든 프로젝트**의 미청구 세션(대관 종류, 취소 제외)·작업을 프로젝트별로 묶어 보여 준다. 내부 지원 프로젝트는 빠진다.
- 행마다 [청구 안 함] — 지금과 같은 토글(대기함에서 빠지고, '청구 안 함 보기'로 되돌릴 수 있다).
- 검색은 프로젝트 이름·아티스트·제작/운영·소속을 함께 본다 → "도너츠"로 그 기획사 프로젝트를 한 번에 모아 체크.
- 체크한 항목으로 [청구서 만들기] → 3-2.

### 3-2. 청구서 작성 (`/invoices/new?items=s12,t34,…`)
```
청구처*   [도너츠컬처            ▾]  추천: 도너츠컬처 · 진혁 · 정효빈
제목      [도너츠컬처 10월 청구          ]
발행일    [2026. 10. 31.]          ☑ 부가세 포함

날짜     내용                                   금액
10/02   [10월 2일 · 진혁 · 녹음            ]   [   300,000]   ✕
—       [내 안의 그대 - 믹싱                ]   [          ]   ✕
—       [내 안의 그대 - 마스터링            ]   [          ]   ✕
        [+ 줄 추가] (계약금·출장비 등 — 세션·작업과 연결되지 않는 줄)

할인 [0] 원 / [0] %          공급가 · 할인 · VAT · 총액
[견적서] [내역서] [거래명세서] 미리보기           [청구서 발행]
```
- **내용·금액은 전부 직접 쓴다.** 내용은 항목에서 미리 채워 두지만 고칠 수 있다. 금액은 세션 확정액(이미 적어 둔 값)만 채우고 나머지는 빈칸.
- 단가표 산정·기본가/초과 분해·작업 종류 기본 단가 채움은 **없다**(§6-1). 작업은 이미 금액을 적어 둔 경우만 채운다.
- 줄을 ✕로 빼면 그 항목은 대기함에 남는다. 빈 금액은 발행을 막는다(0원은 지금처럼 확인 후 허용).
- 청구처 추천 칩 = 고른 항목들이 속한 프로젝트의 당사자 전부(제작/운영·소속·아티스트). 지금처럼 **반드시 직접 고른다.**
- 제목 기본값: 한 프로젝트면 `{프로젝트} 청구`, 여러 프로젝트면 `{청구처} {M}월 청구`.
- 미리보기 PDF 3종·채번·발행 알림·스냅샷(청구처 정보)은 지금과 같다.
- 발행하면 세션은 '완료', 작업은 'Completed'로(지금 규칙 그대로) — 그리고 대기함에서 빠진다.

### 3-3. 프로젝트 화면 '청구' 탭
- **청구서 만들기 폼은 없앤다.** 대신 이 프로젝트의 청구서 목록(다른 프로젝트와 섞인 청구서 포함) + 미청구 항목 요약 + **[이 프로젝트 항목으로 청구서 만들기]**(대기함을 이 프로젝트로 걸러 연다).
- 청구 경로를 대기함 하나로 모은다(경로가 둘이면 규칙이 갈린다 — 지금 CLAUDE.md의 '청구 생성 경로 = 하나' 원칙 유지).

### 3-4. 그 밖
- 대시보드 '청구 필요' 카드 → 대기함으로 연결.
- 청구서 목록·상세의 '프로젝트' 칸: 한 프로젝트면 그 이름, 여러 프로젝트면 `여러 프로젝트 (3)` + 상세에서 목록.

## 4. 단가표 제거

| 대상 | 처리 |
|---|---|
| 세션 폼 '단가 항목' 칸 | 삭제 |
| 촬영 구간 입력(반입·촬영·철수) | 삭제(사용 0건). 시작~종료 시간만 |
| 세션 소요 프리셋 1Pro/2Pro… | 단가 기준시간 대신 **예약 기본값의 기본 세션 시간**을 1단위로 |
| `sessionRateAmount`·`computeCharge`·청구 라인 분해 | 삭제. 세션 금액 = 확정액(`billing_amount`)뿐 |
| 프로젝트 목록 '금액'(예상액) | 세션은 확정액만, 작업은 입력 금액만 합산(산정 예상액 없음) |
| 환경설정 '단가표' 화면 | 삭제(홈페이지 공개 가격표는 별개 — 동기화 안 함 원칙 그대로) |
| `rate_items`·`rate_categories`·`session_segments` 테이블, `sessions.rate_item_id` | **읽지 않음**. 데이터는 4단계에서 삭제 |
| 작업 종류 카탈로그의 '기본 단가' | 삭제(§6-1). 작업 금액은 청구서에서 |

## 5. 데이터 변경

테이블 구조 변경은 **없다**.
- `invoices.project_id`: 이미 NULL 허용. 한 프로젝트 청구서면 그 id, 여러 프로젝트면 NULL.
- 청구서 ↔ 프로젝트 연결은 **라인에서 파생**한다(세션·작업의 project_id). 프로젝트 청구 탭·업체 상세·프로젝트 목록 할인 합계가 이 파생을 쓰도록 바꾼다.
  - 여러 프로젝트 청구서의 **할인**은 라인 금액 비례로 프로젝트에 배분(매출 화면이 이미 쓰는 `ATTR_SUPPLY`와 같은 규칙).
- 자유 라인 = `task_id`·`session_id` 둘 다 NULL인 `invoice_items`(이미 허용). 날짜는 입력값 또는 발행일.
- 기존 청구서 132건은 그대로(모두 한 프로젝트라 `project_id`가 채워져 있다).

## 6. 확정된 결정 (2026-10-13)

1. 작업 종류의 '기본 단가' = **없앤다.** 작업 금액은 청구서에서 직접 입력하고, 작업 종류 설정의 단가 칸도 삭제한다.
2. 믹싱·마스터링 '세션' = **대기함에 올리지 않는다**(지금 규칙 유지 — 이중 청구 방지). 작업이 없는 후반작업 세션은 대기함 위에 "작업을 만들어야 청구할 수 있는 후반작업 세션 N건"으로 알린다.
3. '예정' 세션 = **보인다**(흐리게, 체크 시 '완료로 바꿀까?' 확인) + **'완료만' 필터**.

## 7. 진행 순서

1. 데이터: 청구 후보 전역 조회(`listBillableItems` — 필터), 새 청구 생성(`createInvoice` — 라인 배열 입력: session/task/free + 설명·금액), 청구서↔프로젝트 파생 조회
2. 화면: 대기함 → 작성 → 미리보기 PDF 연결
3. 프로젝트 청구 탭 정리, 옛 `/projects/:id/invoices/from-tasks` 제거(대기함으로 302)
4. 단가표 제거(세션 폼·설정 화면·산정 코드) + 촬영 구간 제거
5. 대시보드·청구 목록 연결, CLAUDE.md 불변식 갱신(청구 경로·미청구 신호·단가 관련)
6. 운영 백업으로 비교: 기존 청구서 132건의 목록·매출·외주 정산 숫자가 그대로인지
