# 개편 5단계 — '완료' 개념 없애기 (설계)

> 2026-10-13 작성. 사용자 지시: "완료라는 개념을 없애자. 예약만 하고 완료는 하지 말자. 일정 취소는 스케줄 기록을 위해
> 필요하다. 완료는 작업자들이 누르는 걸 종종 건너뛰니 버튼이 무용지물일 때가 많고, 완료했는지에 대한 신뢰도도 낮다.
> 스케줄링을 하고, 작업 수주를 받고, 청구를 한다 — 이 개념만 남기자."

## 1. 목표

```
지금:  예약(예정) → [완료] 버튼 → 청구          작업: 등록(대기) → [완료] 버튼 → 청구
5단계: 예약 → 청구 (취소만 상태로 남음)          작업: 등록(수주) → 청구
```

- 세션·작업의 **완료 버튼을 없앤다**. 상태는 세션의 '취소'만 남는다(스케줄 기록용).
- '완료'를 판단 근거로 쓰던 곳은 **날짜**(세션)와 **청구 여부**(세션·작업)로 바꾼다 — 사람이 누르는 버튼이 아니라 기록에서 나오는 사실이다.

## 2. 지금 '완료'가 쓰이는 곳

| 곳 | 지금 | 5단계 |
|---|---|---|
| 세션 행·캘린더 팝오버·프로젝트 목록 펼침 | `− 완료`/`✓ 완료` 토글 | **삭제**. '일정 취소'만 남김 |
| 작업 행 | 완료 토글 | **삭제** |
| 프로젝트 목록 3탭(진행 중·청구 필요·완료) | '예정 세션 없음 + 미완료 작업 없음'이면 끝난 프로젝트 | 날짜·청구로 판정(§3-1) |
| 청구 대기함 | 예정 세션·대기 작업은 흐리게 + 체크 시 '완료로 바꿀까?' 확인, '완료만' 필터 | 날짜로 판정(§3-2) |
| 청구서 발행 | 세션 → '완료', 작업 → Completed로 바꿈. 작업 청구 시 지난 믹싱 세션도 완료 | **상태를 바꾸지 않는다** |
| 후반작업 알림(대기함 위) | 완료 또는 날짜 지난 예정 믹싱 세션 | 날짜 지난 믹싱 세션 |
| 대시보드 '내 할 일' | 내 다가오는 세션 + 내 **미완료** 작업 | §3-3 |
| 세션 상세의 청구 안내 줄 | '완료 시 청구' / '청구 가능' | 날짜 기준 |

## 3. 새 규칙

### 3-1. 프로젝트 목록 3탭
| 탭 | 조건 |
|---|---|
| 진행 중 | **오늘 이후 세션**(취소 제외)이 있다 |
| 청구 필요 | 오늘 이후 세션은 없고, 미청구 항목(지난 세션·작업)이 있다 |
| 완료 | 오늘 이후 세션도 없고 미청구 항목도 없다(활동은 있었음) |

- '청구 필요 N' 배지는 지금처럼 어느 탭에서든 뜬다(진행 중인데 지난 세션이 미청구면 진행 중 탭에 배지).
- 지금 '진행 중'에 남아 있는 이유의 대부분(완료를 안 누른 지난 세션)이 사라진다.

### 3-2. 청구 대기함
- **지난 세션(오늘 포함)·작업 = 보통 항목.** 작업은 등록되면(수주) 청구할 수 있다.
- **오늘 이후 세션 = 흐리게**, 체크하면 "아직 날짜가 안 된 세션입니다. 청구할까요?" 확인(계약금처럼 미리 청구하는 경우).
- '완료만' 필터 → **'지난 일정만'**.

### 3-3. 대시보드 '내 할 일'
완료가 없으면 '미완료 작업'이라는 목록이 성립하지 않는다.
- **추천: 내 다가오는 세션만 남긴다.** 작업은 '할 일'이 아니라 '수주한 일'이고, 끝났는지는 청구로 드러난다.
- 대안: 내 작업 중 **미청구**를 보여 준다(엔지니어가 청구를 직접 하지 않으면 계속 쌓여 보인다).

## 4. 데이터

**스키마·데이터 변경 없음.**
- `sessions.status`: 코드는 **'취소'냐 아니냐만** 본다. 기존 '완료'·'예정' 값은 그대로 두고 읽지 않는다(되돌릴 근거로 남는다). 취소를 되돌리면 '예정'으로.
- `track_tasks.status`: 읽지도 쓰지도 않는다. 새 작업은 기본값('Pending') 그대로.
- 3단계 이후 추가한 '청구 시 완료 처리'·'지난 믹싱 세션 완료' 코드와 1회 이행(`postprod_sessions_billed_complete_v1`)은 의미가 없어지므로 코드를 지운다(이미 운영에 적용된 값은 그대로 — 해가 없다).
- 컬럼 삭제는 하지 않는다(4단계처럼 지울 이득이 크지 않고, 값이 남아 있으면 판단 근거를 되짚을 수 있다).

## 5. 확정할 것

1. **작업의 완료 버튼도 없앤다** — 지시의 '스케줄 → 수주 → 청구'에 맞춰 세션·작업 모두. (추천)
2. 프로젝트 3탭 = §3-1(오늘 이후 세션 / 미청구). (추천)
3. 대기함의 오늘 이후 세션 = 흐리게 + 확인, 필터는 '지난 일정만'. (추천 — 대안: 아예 숨김)
4. '내 할 일' = 다가오는 세션만. (추천 — 대안: 내 미청구 작업)

## 6. 진행 순서

1. 완료 버튼·토글 라우트 삭제(세션 `/sessions/:id/status`는 취소 토글용으로 남기고 '완료' 값은 거부, 작업 `/projects/tasks/:id/status` 삭제)
2. 판정 교체 — 프로젝트 3탭·미청구 신호·대기함·후반작업 알림·내 할 일·세션 청구 안내 줄
3. 청구서 발행의 상태 변경·지난 믹싱 세션 완료 코드 삭제
4. 테스트(완료 토글 테스트 삭제, 판정 테스트를 날짜 기준으로) · CLAUDE.md 불변식 갱신
