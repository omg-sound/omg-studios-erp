# 개편 1단계 — 빠른 생성 (설계 · 2026-10-13 구현)

> 2026-10-13 작성. 전체 개편 방향·확정 결정은 메모리 `erp-redesign-2026-10` 참조.
> 개편 단계: **1 빠른 생성** → 2 곡 계층 제거(작업 평탄화) → 3 청구 대기함·자유 라인 청구서(단가표 제거) → 4 정리.

## 1. 목표

프로젝트 화면을 거치지 않고, 어디서든 **"+ 새로 만들기" → 프로젝트 이름 + 일정 → 저장**으로 세션·작업을 만든다.
아티스트·제작사·엔지니어 같은 상세는 기본으로 접혀 있고, 필요할 때만 펼쳐 기입한다.

| | 지금 | 1단계 후 |
|---|---|---|
| 세션 하나 예약 | 프로젝트 목록 → 새 프로젝트 → 저장 → 세션 탭 → 새 세션 추가 → 저장 (화면 3개) | 새로 만들기 → 이름·날짜·시간 → 저장 (화면 1개) |
| 믹스 작업 하나 | 프로젝트 → 곡·콘텐츠 탭 → 곡 추가 → 작업 추가 (화면 2개 + 곡 생성) | 새로 만들기 → [작업] → 이름·종류 → 저장 |

## 2. 범위

**포함**
- 전역 진입점 `/new` (세션·작업 공용 폼)
- 프로젝트 이름 콤보: 기존 프로젝트 선택 또는 새 이름이면 자동 생성
- 상세 정보 접힘 섹션 (프로젝트 공통 정보 / 이 세션·작업 정보)
- 작업 생성 시 곡을 자동으로 처리 (곡명이 있으면 그 곡, 없으면 프로젝트명으로 된 곡을 찾거나 만듦)
- **청구 쪽 임시 패치**: 단가 항목 없는 세션도 청구 후보에 올리고, 금액은 직접 입력

**제외 (뒷 단계)**
- 곡 계층 제거 → 2단계. 1단계의 자동 곡은 2단계 이전 때 `곡명` 텍스트로 흡수되므로 버려지는 데이터가 없다.
- 단가표·할증·촬영 구간 과금 제거 → 3단계. 1단계에서 단가 항목은 접힌 상세로 옮기기만 한다.
- 프로젝트 목록 3탭·묶음 보기 화면 → 3·4단계.

## 3. 진입점

| 위치 | 동작 |
|---|---|
| 사이드바 상단 **+ 새로 만들기** 버튼 (전 화면) | `/new` |
| 단축키 `n` (입력 칸 밖에서) | `/new` — 기존 `g` 니모닉 단축키와 같은 가드 사용 |
| 일정(캘린더) 날짜 칸의 `+` | `/new?date=YYYY-MM-DD` |
| 대시보드 | `/new` 버튼 |
| 프로젝트 상세 세션 탭 '새 세션 추가' | 같은 폼 컴포넌트, 프로젝트 고정(콤보 대신 이름 표기) |
| 프로젝트 목록 **+ 새 프로젝트** | **+ 새로 만들기**(`/new`)로 교체. `/projects/new`는 `/new`로 302 |

저장 후 이동은 기존 `?return=` + `safePath` 규약을 따른다. return이 없으면 일정 캘린더의 해당 월로 가서 방금 만든 세션 팝오버를 연다(작업이면 프로젝트 곡·콘텐츠 탭).

## 4. 폼 구조

```
┌ 새로 만들기 ──────────────────────────────────────────┐
│  [ 세션 ]  [ 작업 ]                                    │
│                                                        │
│  프로젝트  [ 아이유 정규 6집          ▾ ]  ← 필수       │
│            아이유 · 이담엔터 · 세션 4건 · 최근 10/2    │  (기존 선택 시 요약)
│            ＋ '새 이름' 새 프로젝트로 만들기            │  (새 이름일 때)
│                                                        │
│  ── 세션 ──                                            │
│  [10/14] [14:00] – [18:00] [10/14]  □ 종일             │
│  종류 [녹음 ▾]   장소 [A룸 ▾]                          │
│  ⚠ 같은 룸에 이 시간대 예약이 이미 있습니다            │
│                                                        │
│  ── 작업 ──                                            │
│  종류 [믹스][튠][마스터링][기타 ▾]   곡명 [______](선택)│
│  작업일 [______](선택)                                 │
│                                                        │
│  ▸ 상세 정보   아티스트 아이유 · 엔지니어 김OO          │  ← 접힘, 채워진 값 요약
│  ┌────────────────────────────────────────────────┐  │
│  │ 프로젝트 정보  (이 프로젝트의 모든 세션·작업 공통) │  │
│  │   아티스트 · 제작/운영 · 고객측 담당자 · PM       │  │
│  │   □ 내부 지원(청구 안 함)                        │  │
│  │ 이 세션 정보                                      │  │
│  │   예약 담당자 · 담당 엔지니어(+외주 지급단가)       │  │
│  │   담당 디렉터 · 단가 항목 · 외부 장소 주소 · 메모   │  │
│  │ 이 작업 정보                                      │  │
│  │   담당 엔지니어(+외주 지급단가) · 금액 · 메모       │  │
│  └────────────────────────────────────────────────┘  │
│                                         [ 저장 ]       │
└────────────────────────────────────────────────────────┘
```

- **필수 칸**: 세션은 프로젝트 이름과 날짜. 시간은 예약 기본값 소요시간으로 채운다. 작업은 프로젝트 이름과 종류.
- **본문에 남기는 칸**: 세션 종류와 장소. 둘 다 기본값이 있어 안 건드려도 되지만, 캘린더 표시와 룸 겹침 판정에 직결돼서 접어 두면 오예약이 생긴다.
- **접힘 요약 줄**: 상세에 값이 있으면 `▸ 상세 정보` 옆에 한 줄로 요약한다. 편집 화면에서 접혀 있어도 내용이 숨지 않는다.
- **촬영 구간**: 촬영 대관 종류일 때 지금처럼 시간 줄을 대체한다. 3단계에서 존폐를 정한다.
- **기존 폼 부품을 그대로 재사용**: `dateCombo`·`timeBox`·`roomSelect`·`personCombo`·`engineerRow`·`managerOptions`. 1단계는 배치만 바꾸고 입력 위젯은 새로 만들지 않는다.

## 5. 프로젝트 이름 콤보

- 타이핑하면 기존 프로젝트 제목을 검색한다(최근 활동순, 완료된 프로젝트 포함). 후보 표시는 `제목 · 아티스트 · 최근 일정`.
  기존 `/projects/suggest` 엔드포인트를 확장해서 쓴다.
- 기존 프로젝트를 고르면 `/new?project_id=…`로 **다시 불러온다**(입력한 본문 칸은 쿼리로 유지). 서버가 그 프로젝트 값으로 상세의 '프로젝트 정보' 칸을 채워 그린다 — 아티스트·담당자 콤보를 JS로 다시 초기화하지 않아도 된다. 고른 뒤엔 이름 칸 대신 프로젝트 표기 + [변경].
- 목록에 없는 이름이면 `＋ '…' 새 프로젝트로 만들기`가 뜨고, 저장할 때 새 프로젝트가 생긴다.
- **동명 처리 = 항상 확인받는다**(2026-10-13 사용자 결정 — 자동 연결 안 함):
  - `project_id` 없이 제목만 왔는데 같은 제목(공백 정리 후 정확 일치)이 1건 이상 있으면, 서버는 **저장하지 않고** 폼을 다시 렌더한다. 그 위에 "같은 이름의 프로젝트가 있습니다"와 함께 후보(제목 · 아티스트 · 최근 일정)마다 **[이 프로젝트에 추가]**, 그리고 **[새 프로젝트로 만들기]**를 보여준다. 입력값은 모두 보존한다.
  - [새 프로젝트로 만들기]는 hidden `project_new_confirmed=1`로 재제출한다. 서버는 이 마커가 있을 때만 동명 생성을 허용한다(세션 겹침의 `override_conflict`와 같은 '경고 ≡ 차단 + 확인 마커' 구조).
  - 0건이면 확인 없이 새로 생성한다.
  - 화면도 타이핑 중에 같은 판정을 미리 보여준다("같은 이름의 프로젝트가 있습니다 — 목록에서 고르거나 저장 시 확인").

## 6. 프로젝트 정보 덮어쓰기 규칙 (중요)

상세의 '프로젝트 정보'는 묶음 공통이라, 고치면 그 프로젝트의 다른 세션·작업에도 반영된다.

- **새 프로젝트**: 보낸 값을 그대로 저장한다.
- **기존 프로젝트**: JS가 프로젝트 정보 칸이 실제로 바뀌었을 때만 hidden `project_info_touched=1`을 세팅한다. (구현: 이벤트 추적이 아니라 **로드 시점과 제출 시점의 칸 값 비교** — 콤보 위젯이 hidden 값을 바꾸는 방식과 무관하게 정확하다.) **마커가 없으면 서버는 프로젝트 칸을 무시한다.** 섹션을 안 열고 저장해도 빈 칸이 기존 아티스트를 지우면 안 된다(세션 구간의 '칸이 없으면 안 건드린다' 규약과 같은 이유).
- 바뀐 경우 저장 버튼 위에 "프로젝트 정보가 이 프로젝트 전체에 반영됩니다" 안내를 띄운다.

| 작업일 | `track_tasks.work_date TEXT`(YYYY-MM-DD, NULL 허용) `addColumn`. 프로젝트 곡·콘텐츠 탭의 작업 폼에도 같은 칸. 청구 라인의 `item_date` 스냅샷은 `work_date`가 있으면 그것, 없으면 지금처럼 생성일(KST) |

**청구 쪽 임시 패치** (3단계에서 청구가 통째로 바뀌기 전까지 매출이 새지 않게)
- `listBillableSessionsForProject`·`computeInvoiceDraft`의 `rate_item_id IS NOT NULL` 조건을 뺀다.
- 단가 항목이 없는 세션은 산정치 0으로 후보에 오르고, 금액 칸에 직접 입력한다. 0원 확인(`confirmZero`) 흐름은 그대로 둔다.
- 라인 설명은 `날짜 · 아티스트 · 세션 종류`(단가 항목명 대신)로 쓴다.
- 회귀 테스트 `billing-radar.test.js`의 '후보 ≡ 미청구 집계' 정합을 그대로 지킨다.

## 8. 기존 화면 변화

- 세션 편집 폼(프로젝트 세션 탭·캘린더 팝오버의 편집)도 같은 구조로 바꾼다. 상세는 접고 요약 줄을 보인다.
- 프로젝트 상세 '정보' 탭은 그대로 둔다(같은 데이터를 고치는 또 하나의 입구).
- 프로젝트 목록·청구 탭·대시보드 집계는 변경하지 않는다.

## 9. 테스트

- `/new` 세션: 새 이름이면 프로젝트 1건과 세션 1건 생성, 캘린더 동기화 호출
- `/new` 세션: 기존 프로젝트 선택 + 마커 없음 → 프로젝트 칸 불변(빈 값으로 덮어쓰지 않음)
- 동명: 0건이면 바로 생성 / 1건 이상이면 저장 안 됨·입력 보존·후보 표시 / 확인 마커가 있으면 생성 / 후보 선택 시 그 프로젝트에 추가
- 작업일: 저장·편집·NULL, 청구 라인 `item_date` 반영
- `/new` 작업: 곡명 유무에 따라 곡 재사용·생성
- 트랜잭션: 세션 생성이 실패하면(겹침 거부 등) 새 프로젝트도 남지 않음
- 단가 없는 세션이 청구 후보에 오르고 미청구 집계와 일치
- 기존 `select-preserve.test.js`: 접힌 섹션 안의 select도 현재값 보존

## 10. 확정된 결정 (2026-10-13)

1. 진입 형태 = **전용 페이지 `/new`**
2. 작업일 = **선택 칸으로 추가**(`track_tasks.work_date`)
3. 동명 프로젝트 = **항상 확인받기**(§5)
